# create_chapter — Создать главу

> **Канонический пример** (фаза 3b): автоматизация (M1).
>
> Автоматизация и форма создания объекта. Форма выводится из типа объекта: отдельный тип Form отклонён как дублирование данных (ADR-0010 §3.4).

| | |
|---|---|
| Имя файла | `create_chapter (AUTO-01J8Z6M4K2Q7V9X3N5B0C1D5A3).md` |
| Префикс типа | `AUTO` |
| Идентификатор | `01J8Z6M4K2Q7V9X3N5B0C1D5A3` (ULID, 26 символов) |
| Роль поля `title` | ключ (D-0063) |

Форма создания **выводится** из типа объекта: отдельный тип `Form` отклонён как дублирование данных (ADR-0010 §3.4). Поля формы — эффективный набор свойств типа, порядок — порядок в `ObjectType.properties`, обязательность — `Property.required` с учётом переопределений и аспектов.

`form_fields` сужает состав и задаёт порядок: два свойства и одно поле системного контракта. Поля контракта адресуются с префиксом `sys:` (`sys:title`), потому что `title` — системный атрибут, а не объект `Property` (ADR-0010 §3.3, NAME_MAPPING §7.2). Запись sys-поля wikilink-ом нормативному виду противоречит (находка F-3.13) и в канонических примерах не используется.

Плейсхолдеры `defaults`: `{next_sequence}` вычисляется как max(`order`) среди соседей плюс `sequence_step` (ADR-0010 §2.2). `require_confirmation: true` — задел; в MVP подтверждение требуется всегда (Q-36 = A).

Отрисовка кнопок перехода к соседним главам относится к реализации и здесь не описывается (правило L-1).

## Что демонстрирует пример

- смешение ссылок на `Property` и адресов `sys:` в одном списке (meta.r15)
- значения по умолчанию с плейсхолдером последовательности
- `title` не является объектом `Property`: это поле системного контракта
