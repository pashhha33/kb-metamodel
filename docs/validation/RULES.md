# Правила валидации метамодели

Каталог всех правил. Единственный нормативный источник для валидатора плагина:
каждое правило имеет стабильный ID, уровень, формулировку и текст сообщения.
JSON Schema в `schema/` покрывает только структурную часть; межобъектные правила
(ссылочная целостность, наследование, активация аспектов) реализуются валидатором
(модуль реализации — см. `docs/plugin/ARCHITECTURE.md` §4.1).

**Измеренное покрытие — в §14.1.** Оно является следствием решения Q-50 = C (D-0062) и
пересчитывается скриптом, а не вписывается вручную.

## 1. Уровни и политика применения

### 1.1. Уровни

| Уровень | Значение | Реакция плагина |
|---|---|---|
| `error` | Нарушает модель. Данные нельзя считать корректными | Запись через API плагина отклоняется; при внешнем изменении — диагностика, данные **не перезаписываются** |
| `warn` | Подозрительно, но допустимо | Запись разрешена; диагностика показывается |
| `info` | Стилистическое замечание | Только в отчёте о качестве метамодели |

### 1.2. Шесть видов проверок (Спецификация §19)

Черновик объявлял шесть видов проверок, не формализуя ни одного правила. Соответствие:

| Вид из spec §19 | Что проверяет | Группы правил этого каталога |
|---|---|---|
| 1. Предварительная | Достаточно ли данных для начала проверки | `contract.*` |
| 2. Техническая | Форматы, типы значений, регулярные выражения | `naming.*`, `format.*` |
| 3. Структурная | Обязательность, кардинальность, состав полей | `property.*`, `classif.r10…r12` |
| 4. Семантическая | Ссылочная целостность, типы целей, наследование, активация | `link.*`, `inherit.*`, `aspect.*`, `relation.*` |
| 5. Представлений | Корректность определений `View` и `Automation` | `view.*` |
| 6. Постпроверка | Сохранённое значение перечитано и соответствует схеме | повторный прогон 1–5 после записи |

### 1.3. Когда выполняется проверка

| Триггер | Объём проверки | Основание |
|---|---|---|
| Запись через API плагина | затронутый объект + его исходящие ссылки | v1.1 §18.4: единый сервис записи |
| Внешнее изменение файла (панель Properties, ручной YAML, другой плагин) | затронутый объект | v1.1 §18.5 п.1 |
| Загрузка метамодели | все определения M1 + `inherit.*` + конфликты аспектов | ADR-0008 §3.4: конфликт аспектов — ошибка загрузки |
| Явная команда «Проверить хранилище» | всё хранилище | v1.1 §18.5 п.5: полная проверка отдельной командой |
| Перед разрушительной операцией | затрагиваемый набор + предпросмотр | v1.1 §15.4 п.5–6 |

**Локальность.** Изменение одного свойства не должно вызывать полную проверку хранилища.
Полная проверка доступна отдельной командой.

### 1.4. Запрет молчаливой перезаписи

Нормативный принцип S6 (Спецификация §19, v1.1 §15.5, §18.5):

> Некорректное значение **не удаляется и не перезаписывается автоматически**.
> Плагин сообщает о проблеме и предлагает исправление. Автоматическое исправление
> допустимо только в явно подтверждённой пользователем операции.

Если метамодель стала некорректной, плагин продолжает использовать **последнюю корректную схему**
и сообщает о конфликте, а не применяет частично загруженную.

## 2. Системный контракт (`contract.*`)

| ID | Уровень | Правило | Сообщение |
|---|---|---|---|
| `contract.r1` | error | `id` присутствует | «У объекта отсутствует id» |
| `contract.r2` | error | `id` — валидный ULID: 26 символов, Crockford Base32 | «id не соответствует формату ULID: {факт}» |
| `contract.r3` | error | `id` уникален в хранилище | «id {значение} используется несколькими объектами: {список файлов}» |
| `contract.r4` | error | `type` присутствует и есть в реестре типов | «Неизвестный тип объекта: {факт}» |
| `contract.r5` | error | `type` не является абстрактным типом (`is_abstract: true`) | «Тип {значение} абстрактный, экземпляры недопустимы. Выберите один из: {список конкретных наследников}» |
| `contract.r6` | error | `title` присутствует и не пуст после trim | «У объекта типа {type} не заполнен title» |
| `contract.r7` | error | `created_at`, `updated_at` присутствуют и соответствуют формату (§6) | «Некорректная дата в поле {поле}: {факт}» |
| `contract.r8` | error | `status` присутствует и входит в enum `status` | «Неизвестный статус: {факт}. Допустимы: {список}» |
| `contract.r9` | warn | `updated_at` ≥ `created_at` | «updated_at раньше created_at» |
| `contract.r10` | error | `id` во frontmatter совпадает с `id` в имени файла | «id в файле ({файл}) не совпадает с id в frontmatter ({значение})» |
| `contract.r11` | error | Имя файла соответствует шаблону `{title} ({type_prefix}-{id}).md` | «Имя файла не соответствует каноническому формату: {факт}» |
| `contract.r12` | warn | `title` в имени файла не длиннее 60 символов | «title длиннее 60 символов; в имени файла использовано усечение» |

**Область действия `contract.r6`, `r11`, `r12` (уточнение D-0063).** Поле `title` играет две роли
(норма — `docs/metamodel/NAME_MAPPING.md` §0): ключ у определений, адресуемых по ключу
(`Property`, `PropertyType`, `RelationType`, `Facet`, `Aspect`, `Automation`), и отображаемое
название у остальных объектов. `contract.r6` (присутствие и непустота) применяется ко всем объектам.
`contract.r11` и `contract.r12` (шаблон имени файла и усечение до 60 символов) применяются только
к объектам, у которых `title` является отображаемым названием: у определений-ключей техническая
часть имени файла строится по ключу, а подпись берётся из `label`.

## 3. Имена и форматы (`naming.*`, `format.*`)

| ID | Уровень | Правило | Сообщение |
|---|---|---|---|
| `naming.r1` | error | Каждый `key` свойства соответствует `^[a-z][a-z0-9_]{0,63}$` | «Недопустимый ключ свойства: {факт}» |
| `naming.r2` | error | `key` не начинается с зарезервированных префиксов `cat_`, `label_`, `sb_` | «Ключ {факт} использует зарезервированное пространство имён» |
| `naming.r3` | error | `key` уникален среди всех `Property` | «Ключ {факт} используется несколькими свойствами: {список}» |
| `naming.r4` | error | `type_prefix` соответствует `^[A-Z][A-Z0-9]{2,11}$` (только ASCII) | «Недопустимый префикс типа: {факт}» |
| `naming.r5` | error | Все кодовые точки `type_prefix` в диапазонах U+0041–U+005A, U+0030–U+0039 | «Префикс {факт} содержит недопустимые символы (возможны омоглифы)» |
| `naming.r6` | error | `type_prefix` уникален по точному совпадению среди конкретных типов и резерва | «Префикс {факт} уже используется типом {тип}» |
| `naming.r7` | error | `type_prefix` присутствует у конкретного типа и отсутствует (`null`) у абстрактного | «Префикс обязателен для конкретного типа / запрещён для абстрактного» |
| `naming.r8` | error | `Facet.key` соответствует `^[a-z][a-z0-9_]{1,30}$` и не начинается с `cat_` | «Недопустимый key фасета: {факт}» |
| `naming.r9` | error | `Facet.key` уникален глобально среди всех фасетов | «key {факт} уже используется фасетом {фасет}» |
| `naming.r10` | error | `label` присутствует у каждого **определения** M1; на экземпляры системных типов (`Relation`, `MediaAsset`) правило не распространяется — для них состав полей задаёт таблица полей типа (D-0066) | «У определения {title} не заполнен label» |
| `naming.r11` | error | Имя бинарного файла соответствует `{title} ({PREFIX}-{id}).{ext}`, расширение сохранено | «Недопустимое имя медиафайла: {факт}» |
| `format.r1` | error | Значение `cardinality` входит в `0..1`, `1`, `0..n`, `1..n` | «Недопустимая кардинальность: {факт}» |
| `format.r2` | error | Значения всех enum-полей входят в соответствующие справочники | «Недопустимое значение {поле}: {факт}. Допустимы: {список}» |
| `format.r3` | info | Значение даты хранится с offset | «Дата без смещения часовой зоны: {факт}» |

## 5. Ссылки и связи (`link.*`, `relation.*`)

| ID | Уровень | Правило | Сообщение |
|---|---|---|---|
| `link.r1` | error | Цель ссылки существует: разрешается либо штатным механизмом ссылок, либо по стабильной части `(PREFIX-ULID)` | «Ссылка ведёт на несуществующий объект: {факт}» |
| `link.r2` | error | Цель ссылки имеет тип из `target_types` свойства | «Свойство {label} ожидает {target_types}, цель имеет тип {факт}» |
| `link.r3` | error | При заданном `target_facet` цель является `Category` этого фасета | «Значение {факт} не относится к фасету {facet}» |
| `link.r4` | error | Ссылка содержит стабильную часть `(PREFIX-ULID)` | «Ссылка не содержит идентификатора цели, разрешение ненадёжно: {факт}» |
| `link.r5` | warn | Alias ссылки не совпадает с актуальным `title` цели | «Подпись ссылки устарела: {факт} вместо {title}» |
| `link.r6` | warn | Ссылка неоднозначна: стабильной части соответствуют несколько файлов | «Неоднозначная ссылка {факт}: найдено {n} файлов» |
| `relation.r1` | error | У `Relation` заполнены `subject`, `relation_type`, `object` | «У отношения не заполнено обязательное поле {поле}» |
| `relation.r2` | error | Тип `subject` соответствует `subject_types` типа отношения (с учётом наследования) | «Субъект типа {факт} недопустим для отношения {relation_type}: ожидалось {список}» |
| `relation.r3` | error | Тип `object` соответствует `object_types` типа отношения | «Объект типа {факт} недопустим для отношения {relation_type}: ожидалось {список}» |
| `relation.r4` | error | Соблюдено `uniqueness_rule` (`unique_triple` — одна тройка субъект-тип-объект; `unique_subject` — один субъект; `unique_object` — один объект) | «Нарушено правило уникальности {rule}: {конфликтующие объекты}» |
| `relation.r5` | error | При `direction: symmetric` обратная связь существует либо связь помечена симметричной явно | «Симметричное отношение {title} не имеет обратной связи» |
| `relation.r6` | error | **Одна связь не существует в двух формах**: нет одновременно ссылки в свойстве и объекта `Relation` для той же пары и того же смысла | «Связь {субъект} → {объект} продублирована: свойство {key} и отношение {title}. Оставьте одну форму (правило повышения)» |
| `relation.r7` | warn | `is_restriction: false` и типы не соответствуют рекомендации | «Не рекомендуется: {relation_type} обычно связывает {subject_types} с {object_types}» |
| `relation.r8` | warn | `valid_to` < `valid_from` | «Дата окончания раньше даты начала» |

## 6. Форматы дат (норматив)

| Случай | Формат | Пример |
|---|---|---|
| `date` | `YYYY-MM-DD` | `2026-10-21` |
| `datetime` | ISO 8601 с offset | `2026-10-21T14:30:00+03:00` |
| Интервал | `*_from` / `*_to`, границы включительны, формат `YYYY-MM-DD` | `valid_from: "1921-01-01"`, `valid_to: "1926-12-31"` |
| Незакрытый интервал | `*_to` отсутствует | действует по настоящее время |

## 8. Наследование типов (`inherit.*`)

Проверяются при загрузке метамодели, а не при правке объекта (ADR-0003 §3.5).

| ID | Уровень | Правило | Сообщение |
|---|---|---|---|
| `inherit.r1` | error | Дочерний тип не изменяет `definition` унаследованного свойства | «Смысл свойства {label} изменён в типе {type}» |
| `inherit.r2` | error | Дочерний тип не изменяет `value_type` унаследованного свойства | «Тип значения свойства {label} изменён в типе {type}» |
| `inherit.r3` | error | Дочерний тип не понижает обязательность (`required: true` → `false`) | «Обязательность свойства {label} ослаблена в типе {type}» |
| `inherit.r4` | error | Дочерний тип не расширяет кардинальность | «Кардинальность свойства {label} расширена в типе {type}» |
| `inherit.r5` | error | Цикл в `parent_type` отсутствует | «Обнаружен цикл наследования: {цепочка}» |
| `inherit.r6` | error | `parent_type` указывает на существующий `ObjectType` | «Родительский тип не найден: {факт}» |
| `inherit.r7` | warn | Глубина наследования больше 5 | «Глубокая иерархия типов ({n} уровней) — проверьте обоснованность» |

## 9. Аспекты (`aspect.*`)

| ID | Уровень | Правило | Сообщение |
|---|---|---|---|
| `aspect.r1` | warn | Значение свойства присутствует, но активирующий аспект не сработал | «Свойство {label} заполнено, но ни одна назначенная категория его не активирует» |
| `aspect.r2` | error | Два активированных аспекта задают несовместимые ограничения одного свойства | «Конфликт аспектов {a} и {b} по свойству {label}: {описание}» |
| `aspect.r3` | error | `trigger_categories` не пуст и все цели существуют и являются `Category` | «Некорректный триггер аспекта {title}: {факт}» |

| `aspect.r5` | warn | Аспект переопределяет свойство, уже заданное типом объекта, с другими ограничениями | «Аспект {title} переопределяет свойство {label}, заданное типом {type}; приоритет у типа» |
| `aspect.r6` | info | `is_active: false` — аспект выключен | «Аспект {title} выключен и не применяется» |

## 10. Определения M1 (`meta.*`)

| ID | Уровень | Правило |
|---|---|---|
| `meta.r1` | error | `Property.value_type` — существующий `PropertyType` из закрытого набора 6 значений |
| `meta.r2` | error | `Property.target_types` задан, если `value_type: reference`; пустой список означает «любой тип» |
| `meta.r3` | error | `Property.target_facet` задан только при `target_types: [category]` |
| `meta.r4` | error | `RelationType.subject_types` и `object_types` ссылаются на существующие `ObjectType` |
| `meta.r5` | error | `Taxonomy.applicable_types` не пуст и элементы разрешимы: wikilink-ссылка на определение `ObjectType` либо голое имя системного типа snake_case (D-0067) |
| `meta.r6` | error | `Facet.taxonomy` и `Category.facet` разрешимы (ссылки только вверх, ADR-0005) |
| `meta.r7` | error | `View.target_types` не пуст; `mechanism` входит в enum |
| `meta.r8` | error | `Automation.trigger` и `mechanism` входят в enum |
| `meta.r9` | error | `MediaAsset.file` присутствует и указывает на существующий файл хранилища |
| `meta.r10` | error | `MediaAsset.role` входит в enum `role` |
| `meta.r11` | warn | Определение M1 имеет `lifecycle: deprecated`, но используется объектами |

## 12. Жизненный цикл (`lifecycle.*`)

Основание — ADR-0009. Архивирование выражается только полем `status`, файл не перемещается.

| ID | Уровень | Правило | Сообщение |
|---|---|---|---|
| `lifecycle.r1` | error | Цель `merged_into` и `supersedes` не имеет `status: archived` — цепочки запрещены | «Цель связи {title} архивная; цепочки замен запрещены. Укажите конечный объект» |
| `lifecycle.r2` | warn | На архивный объект ссылаются активные объекты | «На архивный объект {title} ссылаются активные: {список}» |
| `lifecycle.r3` | error | У объекта не более одного исходящего `merged_into` и не более одного `supersedes` | «Объект {title} имеет несколько связей замены» |
| `lifecycle.r4` | warn | Объект со `status: deleted`, но файл существует и ссылки не переведены | «Объект отмечен удалённым, но ссылки на него остались» |
| `lifecycle.r5` | info | Переход `status` нарушает основной порядок жизненного цикла | «Необычный переход статуса: {откуда} → {куда}» |

`lifecycle.r5` — уровень `info`: Спецификация §15 задаёт основной путь, но обратные переходы
легитимны (архивный объект может быть возвращён в активные).

### 12.1. Процедура слияния (нормативная)

1. Выбор основного объекта пользователем.
2. Предпросмотр: переносимые свойства, затрагиваемые ссылки, конфликты.
3. Резервная копия.
4. Перевод ссылок на основной объект.
5. Создание `Relation` с `relation_type: merged_into`.
6. Присвоение дубликату `status: archived` (файл не удаляется и не перемещается).
7. Откат из резервной копии при сбое любого из шагов 4–6.

## 13. Последовательности и уникальность в области действия (`sequence.*`, `unique.*`)

Основание — ADR-0010. Правила нормативны с версии 0.9.0.

### 13.1. Последовательности

| ID | Уровень | Правило | Сообщение |
|---|---|---|---|
| `sequence.r1` | error | `sequential_parent` и `sequence_key` заданы только парой | «Тип {title} объявлен последовательностью частично: укажите оба поля или ни одного» |
| `sequence.r2` | error | `sequential_parent` — свойство с `value_type: reference` и `cardinality` ∈ {`1`, `0..1`} | «Свойство {key} непригодно как родитель последовательности» |
| `sequence.r3` | error | `sequence_key` — свойство с `value_type: number` и `cardinality: 1` | «Свойство {key} непригодно как ключ порядка» |
| `sequence.r4` | error | Объект типа-последовательности имеет непустое значение `sequence_key` | «Не заполнен ключ порядка {key} у объекта {title}» |
| `sequence.r5` | warn | Разрыв нумерации между соседями | «Между {a} и {b} пропущены значения порядка» |
| `sequence.r6` | error | `sequence_step` > 0 | «Шаг нумерации должен быть положительным» |

### 13.2. Уникальность в области действия

Первое **межобъектное** ограничение модели: проверяется не один объект, а совокупность.

| ID | Уровень | Правило | Сообщение |
|---|---|---|---|
| `unique.r1` | error | Пара (`unique_within`, значение свойства) уникальна в хранилище | «В области {значение родителя} уже есть объект с {key} = {значение}: {файл}» |
| `unique.r2` | error | `unique_within` указывает на свойство того же типа из эффективного набора | «Область уникальности {key} не является свойством типа {type}» |

Реализация требует индекса «значение области → объекты», построенного при загрузке и поддерживаемого
по событиям файлового API. Без индекса проверка была бы O(N) на каждое сохранение.

### 14.1. Покрытие правил JSON Schema

Какие правила обеспечивает машина, а какие остаются обязанностью валидатора — фиксируется
отдельным документом, потому что это проверяемый факт, а не оценка:

- **`docs/validation/RULES_COVERAGE.md`** — матрица: правила по группам, перечень покрытых
  схемой с указанием файла и поля схемы, перечень правил валидатора с причиной по каждому.
- **`docs/validation/rules-coverage.json`** — тот же снимок машиночитаемо (вход для отчётов и тестов).
- Матрица строится из аннотаций `x-rules` в схеме. Политика аннотирования нормативна и описана
  в `RULES_COVERAGE.md`: `x-rules` означает **полное** покрытие правила схемой, частичное
  покрытие описывается в `x-notes` поля и в списке «только валидатор».

Правило без аннотации автоматически попадает в список «только валидатор», поэтому молча потерять
правило нельзя: расхождение между каталогом и схемой обнаруживается при каждой пересборке матрицы.

> Команды пересборки и состав конвейера артефактов — в `docs/README.md` («Конвейер артефактов»).
> В этом каталоге они не приводятся согласно правилу расслоения L-1: каталог правил описывает
> семантику проверок, а не инструменты их пересчёта.

## 15. Структура диагностики (контракт данных валидатора)

Каждая диагностика возвращается в единой структуре — это вход для UI и для отчётов.
Имя типа приведено как контракт данных, а не как предписание реализации:

```typescript
interface Diagnostic {
  ruleId: string;              // 'property.r1'
  level: 'error' | 'warn' | 'info';
  filePath: string;            // путь к объекту
  objectId: string;            // ULID объекта
  propertyKey?: string;        // ключ свойства, если правило о свойстве
  actual?: unknown;            // фактическое значение
  expected?: string;           // ожидаемое (формат, список, тип)
  message: string;             // готовое к показу сообщение на русском
  fix?: {                      // необязательное предлагаемое исправление
    kind: 'set' | 'remove' | 'rename' | 'create-target';
    description: string;
  };
}
```

Правила формирования: `message` всегда на русском и содержит фактическое значение;
`fix` предлагается не для всех правил; применение `fix` — только явной подтверждённой операцией (§1.4).
