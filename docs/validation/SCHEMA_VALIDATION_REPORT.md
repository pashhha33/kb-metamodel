# Отчёт о постройке и проверке JSON Schema (фаза 3a)

Документ фиксирует **что построено, что при этом вскрылось и какие решения требуются**.
Это рабочий отчёт фазы 3a, а не нормативный документ метамодели: нормативны схема
(`schema/`), каталог правил (`docs/validation/RULES.md`) и ADR.

Приоритет источников соблюдён: при расхождении прозы и машиночитаемой записи расхождение
фиксируется здесь как находка, а не «тихо» разрешается в схеме.

каталогу правил, свежесть производных файлов. Скрипт поставлен первым шагом конвейера: ошибка
схемы обнаруживается до сборки, а не прогоном примеров.

**Покрытие каталога схемой: 28 из 114 правил (25 %), в том числе 27 из 83 уровня error.**
86 правил остаются обязанностью валидатора. Это не дефект схемы, а прямое следствие решения
**Q-50 = C (D-0062)**: межобъектные ограничения (разрешение ссылок, уникальность, циклы,
наследование, активация аспектов, соответствие имени файла) в JSON Schema невыразимы.
Полный перечень с причинами — `RULES_COVERAGE.md`.

### 1.1. Почему форма — раздельные файлы (Q-49 = B, D-0061)

| Причина | Пояснение |
|---|---|
| Локальность правки | Изменение одного типа — один файл; diff читаем, ревью возможно |
| Совместное использование определений | `common/` переиспользуется всеми типами: системный контракт определён один раз |
| Цена | Внешние `$ref` не разрешаются большинством потребителей → добавлен шаг сборки производного единого файла (`schema:bundle`). Для плагина схема упаковывается в артефакт сборки, сеть не нужна |

### 1.2. Почему типы генерируются из схемы (Q-50 = C, D-0062)

Схема — единственный источник формы данных. TS-типы, производная схема типа для экземпляров M0
и валидатор формы строятся из неё, поэтому расхождение «документация ↔ код» становится
невозможным по построению: расхождение возникает только между **схемой и прозой**, а его
ловит этот отчёт (см. §2).

В первой половине 3b применялся промежуточный механизм — виртуальные записи индекса типов с фабрикованными идентификаторами | **Закрыто D-0067 (Q-55 = A)**: системный тип записывается голой строкой snake_case (`formats.json#/$defs/system_type_name`); виртуальные записи отменены; условие `meta.r3` возвращено к строгости каталога (`target_types: [category]`); `target_types` медиа-свойств стал точным (`[media_asset]`) |
| **F-3.22** ⚪ | Пример отношения `merged_into` утверждал, что `lifecycle.r1` следует переформулировать с цели связи на источник («из ADR-0009 следует…») | **Не подтверждено — снято.** ADR-0009 §5 формулирует `lifecycle.r1` так же, как RULES.md §12: цель связи замены не имеет `status: archived`. Архивный источник `merged_into` легитимен (шаг 6 процедуры слияния). Ошибка была в тексте примера: `tools/examples/data-relations.cjs` исправлен, каталог, ADR и чекер не менялись |
| **F-3.23** 🟡 | `scope: family` у свойства не указывает, каким ветвям иерархии типов свойство применимо (например, `birth_date` — Context, `part_of` — Work и Activity): значение без указания ветви неоднозначно | Введено поле `Property.applies_to` (0..n ссылок на абстрактные типы) как допущение **A-7**; пустой список означает «все типы» (поведение до поля). Норма уточняется в фазе 3c при описании 12 типов M1 |
| **F-3.24** 🟢 | Фрагмент `m1/media_asset.json` копировал строгость определений M1 (`unevaluatedProperties: false`, допущение A-2), хотя `MediaAsset` — **экземпляр** системного типа: на нём активируется аспект `ai_generated_media` (ADR-0011 §3.3) с полями `prompt`, `model`, `seed`. Аспекты — данные M1, их поля нельзя объявить в схеме статически, и канонический пример обложки отклонялся схемой | **Закрыто D-0068 (Q-56 = A)**: `unevaluatedProperties: true` по прецеденту A-1 (`m0_instance.json`) — состав полей экземпляра определяет метамодель; эффективный набор свойств проверяют межобъектные правила (`aspect.r2`, `media.r5`). Закрытый словарь A-2 сохраняется для определений M1 |
| **F-3.25** 🟢 | Канонические данные писали `source_url: null` при кардинальности 0..1, тогда как схема объявляет `type: string` (null не допускается). Запись пустого необязательного поля нулём не является канонической формой | **Закрыто D-0068 (Q-56 = A)**: пустое необязательное поле **опускается**, а не записывается как `null`; генератор примеров записывает поле только при непустом значении (`tools/examples/generate.cjs`, `data-media.cjs`) |
| **F-3.26** 🟢 | Описание `sequential_parent` во фрагменте `m1/object_type.json` требует «`cardinality: 1`», тогда как нормативное `sequence.r2` (RULES §13) допускает `cardinality ∈ {1, 0..1}`. Description-текст ненормативен, но вводит в заблуждение | **Закрыто в схеме 0.15.0**: description `sequential_parent` приведён к `sequence.r2` (`cardinality ∈ {1, 0..1}`) одним перевыпуском с условием `meta.r16` (D-0072). Обнаружено при написании `entities/object_type.md` (фаза 3c, пачка 1) |
| **F-3.27** 🟢 | **Идентификатор типа не хранится в определении `ObjectType`.** ADR-0005 §3.6 (D-0020) требует проверять `type` экземпляра «по реестру типов (индексу плагина)», `enums.json#/$defs/type_id` — «проверяется по индексу типов», `contract.r5` требует индекса для проверки абстрактности. Но ни одно поле фрагмента `m1/object_type.json` не хранит значение `type_id` (`book`, `person`, …): индекс нечем построить из данных хранилища. Песочница хардкодит соответствие префиксов (`PREFIX_TO_TYPE`: `CHAR → character`, `ORG → organization` — не выводимо из префикса), генератор берёт `type_id` из внешнего реестра `vault-data.cjs`. Произвольные типы, добавляемые как данные M1 (D-0021), объявить нечем | **Закрыто ADR-0012 (Q-65 = A, D-0073)**: обязательное поле `ObjectType.type_id` (EN snake_case, уникален, не совпадает с M1-типами, неизменяем) — по образцу `Facet.key` (ADR-0007). Индекс типов строится из данных; хардкод соответствия префиксов удалён из песочницы; правила `naming.r12` (схема), `naming.r13` (валидатор). Варианты B (конвенция от префикса — уже нарушена `CHAR`/`ORG`) и C (отложить) отклонены. Обнаружено при написании `entities/object_type.md` (фаза 3c, пачка 1) |

## 4. Частичное покрытие правил схемой

Правила ниже **не аннотированы** как покрытые (политика — `RULES_COVERAGE.md`), но схема
отсекает часть нарушений. Это осознанный компромисс: аннотация обещала бы больше, чем схема
обеспечивает.

| Правило | Что обеспечивает схема | Что остаётся валидатору |
|---|---|---|
| `meta.r3` | `target_facet` запрещён, если `target_types` не является одиночной ссылкой на категорию **с распознаваемой стабильной частью** `(CAT-ULID)` | распознавание категории по ссылке без стабильной части; проверка, что цель действительно `Category` этого фасета (`link.r3`) |
| `meta.r5` | `applicable_types` обязателен и непуст | разрешимость ссылок |
| `meta.r7` | `View.target_types` непуст, `mechanism` из enum | разрешимость ссылок; условие `is_active: true` (`view.r1`) |
| `naming.r10` | `label` обязателен в 11 из 12 фрагментов M1 | `MediaAsset` (F-3.12); непустота после trim при локальных символах |
| `sequence.r1` | оба поля присутствуют либо оба отсутствуют (`dependentRequired`) | пара «оба поля со значением `null`» — формально проходит схему |
| `contract.r2` | 26 символов алфавита Crockford | монотонность времени в ULID, коллизии (`contract.r3`) |
| `relation.r8` | оба поля ограничены форматом даты/года | сравнение `valid_to < valid_from` при разных форматах |
| `classif.r3` | значения `cat_*` — списки ссылок | длина списка против `assignment_cardinality` фасета |
| `inherit.r1`, `inherit.r2` | `definition` и `value_type` запрещены в `property_overrides` | сравнение с унаследованным определением в других конструкциях |
| `alias.r3` | `uniqueItems` для `aliases` | дубли с учётом нормализации пробелов и регистра |
