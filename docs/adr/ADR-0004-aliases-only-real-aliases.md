# ADR-0004: `aliases` хранит только реальные псевдонимы

## 1. Контекст и проблема

Черновик v1.1 §1.4 устанавливает правило: «`aliases[0]` — фиксированное место для актуального канонического
значения `название`… Каноническое название намеренно дублируется в `aliases`; это системное правило,
а не ошибка данных». Это зафиксировано как одно из предварительных архитектурных решений (v1.1 §16, п. 2).

Правило существовало как компенсация: при имени файла `{TYPE_PREFIX}-{ID}.md` (вариант A в ADR-0002)
объект недоступен по читаемому имени, и `aliases` возвращали ему эту доступность.

После принятия ADR-0002 (вариант C: имя файла `{title} ({type_prefix}-{id}).md`) читаемое имя уже
содержится в имени файла, и исходная причина правила исчезла.

Дополнительные факты:
- `aliases` — **зарезервированное свойство Obsidian** (`parseFrontMatterAliases`, default property).
  Оно влияет на разрешение ссылок, автодополнение и поиск по всему хранилищу.
- Дублирование одного значения в двух полях требует постоянной синхронизации и порождает класс ошибок
  «`aliases[0]` не соответствует `title`» (зафиксировано как C-11).
- Одинаковые названия у разных объектов допустимы (v1.1 §17.2, п. 4). Помещение названия в `aliases`
  создаёт неоднозначность при автодополнении ссылок, которую придётся разрешать вручную.

## 2. Рассматриваемые варианты

| # | Вариант | Плюсы | Минусы | Последствия |
|---|---|---|---|---|
| A | Сохранить правило v1.1: `aliases[0] = title` | Совместимость с черновиком; объект находится по названию даже при изменении имени файла | Дубль значения; постоянная синхронизация; неоднозначность автодополнения при одинаковых `title`; `aliases` используется не по назначению | Целый класс ошибок целостности и фоновая логика синхронизации |
| **B** | **`aliases` содержит только реальные псевдонимы; правило отменено** | Один источник для названия (`title`); нет синхронизации; `aliases` используется по назначению Obsidian | При переименовании файла старые ссылки на прежнее имя не разрешатся через `aliases` — их обновит штатный механизм Obsidian | Прежнее название можно добавить в `aliases` вручную, если это осмысленно |
| C | Хранить название и в `title`, и в `aliases[0]`, но не синхронизировать | Нет фоновой логики | Два расходящихся значения хуже одного | Худший из вариантов |

## 3. Решение

**Выбран вариант B.** Устанавливается:

1. `aliases` содержит **только** дополнительные имена объекта: варианты написания, сокращения,
   имена на других языках, прежние названия, под которыми объект известен.
2. Правило «`aliases[0]` дублирует `title`» **отменяется**. Позиционная семантика у `aliases` отсутствует:
   порядок элементов не несёт смысла.
3. Единственный источник отображаемого названия — поле `title` (системный контракт).
4. При переименовании объекта плагин **не добавляет** прежнее название в `aliases` автоматически.
   Пользователь может сделать это явно, если прежнее имя значимо.
5. Проверка целостности: `warn`, если `aliases` содержит значение, равное `title` (с нормализацией
   пробелов и регистра) — это избыточный дубль.
6. Проверка целостности: `warn`, если один и тот же псевдоним встречается в `aliases` нескольких объектов —
   это создаёт неоднозначность автодополнения.

## 4. Обоснование

1. **Исчезла причина правила.** ADR-0002 поместил читаемое название в имя файла.
2. **Устраняется дублирование данных** (C-11) и связанный с ним класс ошибок синхронизации.
3. **`aliases` используется по назначению**, заложенному в Obsidian, — как механизм разрешения ссылок
   по альтернативным именам.
4. **Уменьшается объём кода плагина:** не нужна логика поддержания `aliases[0]` при каждом изменении `title`,
   при каждом переименовании и при каждом импорте.
5. **Уменьшается неоднозначность:** при одинаковых `title` у двух объектов автодополнение не получает
   двух одинаковых алиасов сверх двух одинаковых имён файлов.

## 5. Последствия

### Положительные
- Меньше кода, меньше ошибок, меньше фоновых операций записи.
- `aliases` остаётся полностью под контролем пользователя.
- Отменяется часть раздела 17 v1.1 (§17.2, п. 6) — синхронизация `aliases[0]` больше не нужна.

### Отрицательные / стоимость
- **Отменяет решение черновика v1.1 §16, п. 2.** Это изменение, требующее подтверждения, — получено.
- Если пользователь ожидает найти объект по названию через `aliases` при изменённом имени файла,
  это не сработает автоматически. Митигция: штатный механизм Obsidian обновляет ссылки при переименовании.

### Что становится возможным позже
- Осмысленное использование `aliases` для многоязычных названий (`Михаил Булгаков` / `Mikhail Bulgakov`)
  без конфликта с системным правилом.

## 6. Влияние на метамодель

| Элемент | Было | Стало | Тип изменения |
|---|---|---|---|
| `aliases` | `aliases[0]` обязан дублировать `название` | только реальные псевдонимы, порядок не значим | **BREAKING** (закрывает C-11) |
| Правило синхронизации `aliases[0]` | обязательная фоновая операция плагина | удалено | **BREAKING** (removed) |
| Проверки целостности | не было | 2 новых правила уровня `warn` | additive |

## 7. Миграция

- Требуется: да, отложена и тривиальна.
- Что нужно сделать: удалить из `aliases` элементы, равные `title`.
- Когда: вместе с общей миграцией имён (ADR-0001) после MVP.
- Затронутые файлы: все, где применялось правило v1.1.
