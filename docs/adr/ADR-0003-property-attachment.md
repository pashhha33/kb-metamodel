# ADR-0003: Привязка свойств к типу объекта

## 1. Контекст и проблема

Главный структурный пробел черновиков (C-20, критичность 🔴): **нет механизма, связывающего `Property`
и `ObjectType`**. Ни у типа объекта нет списка свойств, ни у свойства нет списка применимых типов.
При этом Спецификация §14 описывает наследование свойств («дочерний тип может уточнять обязательность,
сужать кардинальность, добавлять ограничения и свойства») — наследовать нечего, связь не определена.

Без этой связки плагин не способен построить ни форму создания объекта, ни валидатор. Это блокирует
критерий стабильного ядра MVP.

Дополнительное техническое ограничение, обнаруженное при проверке: панель Properties Obsidian
**не поддерживает вложенные свойства**. Цитата из официальной справки: «Nested properties: To view
nested properties, we recommend using the source mode». То есть структура вида
`properties: [{property: ..., required: true}]` редактируется только в режиме исходного кода.

## 2. Рассматриваемые варианты

| # | Вариант | Плюсы | Минусы | Последствия |
|---|---|---|---|---|
| A | Всё вложенным списком у типа: `properties: [{property, required, cardinality, order}]` | Все ограничения типа в одном месте; одна заметка = полная форма | Вложенный YAML не редактируется нативной панелью; дублирование значений по умолчанию одного свойства в каждом типе | Тяжёлый ручной ввод определений |
| B | Список у свойства: `Property.applies_to: [ObjectType…]` | Плоско, просто | Невозможно переопределить обязательность для конкретного типа; для сборки формы надо прочитать все свойства хранилища | Плохая производительность и бедная выразительность |
| C | Объект-ассоциация `PropertyAssignment` | Максимальная гибкость, в духе реификации | Взрыв числа объектов: 20 типов × 10 свойств = 200 заметок-связок | Неподъёмно для личной БЗ |
| **D** | **Гибрид: плоский список ссылок у типа + значения по умолчанию у свойства + редкие вложенные переопределения** | Плоская часть редактируется нативно; каждый факт хранится один раз; переопределения только там, где нужны | Три места вместо одного; нужен алгоритм разрешения итоговых ограничений | Правила наследования должны быть задокументированы и покрыты тестами |

Пользователь выбрал направление **A** (список у типа). Вариант D — это A с технической доработкой,
которая устраняет два его недостатка: нечитаемость вложенного YAML и дублирование значений по умолчанию.

## 3. Решение

**Выбран вариант D как реализация направления A.** Состав привязки распределяется по трём местам:

### 3.1. `ObjectType` — состав и порядок (плоский список)

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2EF
type: object_type
title: Книга
label: Книга
type_prefix: BOOK
is_abstract: false
parent_type: "[[Произведение (OTYPE-01J8Z6M4K2Q7V9X3N5B0C1D2AA)|Произведение]]"

properties:
  - "[[Издательство (PROP-01J8Z6M4K2Q7V9X3N5B0C1D2AB)|Издательство]]"
  - "[[ISBN (PROP-01J8Z6M4K2Q7V9X3N5B0C1D2AC)|ISBN]]"
  - "[[Количество страниц (PROP-01J8Z6M4K2Q7V9X3N5B0C1D2AD)|Количество страниц]]"
---
```

`properties` — **плоский упорядоченный список ссылок**. Порядок задаёт порядок полей в форме и в таблице.

### 3.2. `Property` — значения по умолчанию

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2AB
type: property
title: publisher
label: Издательство

value_type: reference
target_types:
  - "[[Организация (OTYPE-01J8Z6M4K2Q7V9X3N5B0C1D2AE)|Организация]]"

cardinality: 0..1
required: false
scope: universal
definition: Организация, выпустившая издание.
lifecycle: standard
---
```

| Поле | Значение | Пояснение |
|---|---|---|
| `scope` | `universal` \| `family` \| `specific` | `universal` — свойство применяется ко всем типам автоматически и **не перечисляется** в `ObjectType.properties`. Заменяет дубль `область_применения` + `уровень` (C-21) |
| `cardinality` | `0..1` \| `1` \| `0..n` \| `1..n` | Единый формат для всей метамодели (закрывает C-23) |
| `required` | boolean | Производное от кардинальности для простых случаев, но хранится явно для читаемости |
| `target_types` | список ссылок на `ObjectType` | Только для `value_type: reference`. Пусто = ссылка на объект любого типа |
| `allowed_values` | список | Для перечислимых значений (закрывает C-24). В MVP — только список строк |

### 3.3. `ObjectType.property_overrides` — только исключения (вложенный список)

```yaml
property_overrides:
  - property: "[[ISBN (PROP-01J8Z6M4K2Q7V9X3N5B0C1D2AC)|ISBN]]"
    required: true
    cardinality: 1
```

Используется **только** когда дочерний тип ужесточает правило родителя. Редактируется через UI плагина
(вложенный YAML не поддерживается нативной панелью Properties — это осознанное ограничение).

### 3.4. Алгоритм разрешения итоговых ограничений

Для типа `T` и свойства `P`:

```
1. inherited  = все свойства всех предков T (обход parent_type вверх)
2. own        = T.properties
3. universal  = все Property со scope: universal
4. effective  = union(inherited, own, universal)
5. для каждого P из effective:
     default = ограничения из определения P
     override = последнее найденное property_overrides при обходе от корня к T
     result = override ?? default
6. проверка допустимости ужесточения (см. 3.5)
```

### 3.5. Правила наследования (без изменений из Спецификации §14 — сильное решение S4)

Дочерний тип **может**:
- повысить обязательность (`required: false` → `true`);
- сузить кардинальность (`0..n` → `1..n`, `0..1` → `1`);
- добавить ограничение (`allowed_values`, `target_types` — сужение);
- добавить собственное свойство.

Дочерний тип **не может**:
- изменить смысл унаследованного свойства (`definition`);
- изменить `value_type`;
- понизить обязательность (`required: true` → `false`);
- расширить кардинальность.

Нарушение — ошибка валидации уровня `error`, обнаруживается при загрузке метамодели, а не при редактировании объекта.

## 4. Обоснование

1. **Сохраняет выбор пользователя (направление A):** состав и порядок свойств типа видны в одной заметке типа.
2. **Устраняет дублирование:** значение по умолчанию обязательности и кардинальности хранится один раз —
   в определении свойства. Без этого `publisher` пришлось бы описывать с одинаковыми ограничениями
   в каждом из 20+ типов.
3. **Учитывает ограничение Obsidian:** плоский список редактируется нативной панелью Properties;
   вложенность изолирована в редко используемом `property_overrides`.
4. **`scope: universal` сохраняет трёхуровневую идею** Спецификации §14 (универсальные / семейства /
   специализированные) без введения отдельного поля `уровень`.
5. **Правила наследования не изобретены заново** — взяты готовые и корректные из spec §14.

## 5. Последствия

### Положительные
- Форма создания объекта и валидатор получают полный набор ограничений одним обходом.
- Добавление свойства ко всем типам = одна правка (`scope: universal`), а не 20.
- Переопределения видны явно и их мало — легко проверять.

### Отрицательные / стоимость
- Алгоритм разрешения ограничений нетривиален: нужен модуль с юнит-тестами на все 6 шагов.
- `property_overrides` — вложенный YAML, редактируется только через UI плагина или в source mode.
- Три источника ограничений вместо одного: нужна строгая документация приоритета.

### Что становится возможным позже
- Генерация JSON Schema для каждого типа объекта из разрешённых ограничений.
- Автопостроение форм Bases: `properties` типа → набор колонок, `label` → `displayName`.

## 6. Влияние на метамодель

| Элемент | Было | Стало | Тип изменения |
|---|---|---|---|
| `ObjectType.properties` | отсутствовало | обязательный плоский список ссылок | **BREAKING** (закрывает C-20) |
| `ObjectType.property_overrides` | отсутствовало | необязательный вложенный список | additive |
| `ObjectType.is_abstract` | отсутствовало | обязательное булево | additive (закрывает C-17) |
| `Property.scope` | `область_применения` + `уровень` | одно поле `scope` с enum | **BREAKING** (закрывает C-21) |
| `Property.target_types` | отсутствовало | необязательный список | additive |
| `Property.allowed_values` | отсутствовало | необязательный список | additive (закрывает C-24) |
| `PropertyType` | 8 значений | 6: `text`, `number`, `date`, `datetime`, `boolean`, `reference` | **BREAKING** (закрывает C-22) |
| Формат `cardinality` | 4 разных способа | единый: `0..1`, `1`, `0..n`, `1..n` | **BREAKING** (закрывает C-23) |

## 7. Миграция

- Требуется: да, отложена. Существующих определений свойств в хранилище пока нет.
- Что нужно сделать: при переносе черновиков удалить `Список` и `Список ссылок` как типы значений,
