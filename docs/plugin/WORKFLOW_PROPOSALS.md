# Реестр предложений по рабочим процессам плагина

> **Назначение.** Единая точка приёма предложений пользователя о рабочих процессах (workflows)
> плагина: как создаются, редактируются, связываются и просматриваются объекты хранилища.
> Предложение регистрируется **сразу, как возникло** (защита от потери), маршрутизируется по слою
> и ждёт своей фазы — текущая фаза метамодели не прерывается.
>
> Реестр НЕ меняет семантику метамодели (L-1/L-2, D-0057) и не является планом: план реализации
> строится в фазе 4 (`ROADMAP.md`, `MODULES.md`, приоритеты MVP-фич — Q-05).

## Правила маршрутизации

Каждое предложение при регистрации получает слой и адресата:

| Слой | Признак | Куда идёт | Ворота |
|---|---|---|---|
| **1. Семантика (метамодель)** | Меняет смысл данных: новый тип/свойство/отношение/ограничение (пример: «у задачи нужна повторяемость») | Очередь ADR; ядро заморожено (D-0056) — изменение только через новый ADR | Ответ пользователя + ADR |
| **2. Реализация / UX (плагин)** | Описывает, КАК пользователь что-то делает: формы, панели, хоткеи, drag-and-drop, пакетные операции, вставка из буфера | Фаза 4: `ROADMAP.md`, Q-05 (приоритеты MVP-фич); модульный уровень — `ARCHITECTURE.md` (принято / отложено / отклонено) | Чек-лист готовности, фаза 4 |
| **3. Данные (хранилище)** | Выражается существующими механизмами как данные: `Automation` (формы создания), `View` (представления), аспекты, предметные типы как данные M1 (D-0021) | ADR не нужен: описание типа (3c) или объект канонического хранилища `examples/vault/` | Прогон `npm test` |

Дополнительно:
- Пересечение с открытыми вопросами реализации (Q-45…Q-48) — связывается ссылкой.
- Статусы записи: `зарегистрировано` → `маршрутизировано` → `фаза 4` | `очередь ADR` | `данные M1`
  | `принято (ARCHITECTURE)` | `отложено` | `отклонено`.
- Отклонённое предложение не удаляется (строка сохраняется со статусом и обоснованием).
