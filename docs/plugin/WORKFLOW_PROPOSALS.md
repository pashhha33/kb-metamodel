# Реестр предложений по рабочим процессам плагина

> **Назначение.** Единая точка приёма предложений пользователя о рабочих процессах (workflows)
> плагина: как создаются, редактируются, связываются и просматриваются объекты хранилища.
> Предложение регистрируется **сразу, как возникло** (защита от потери), маршрутизируется по слою
> и ждёт своей фазы — текущая фаза метамодели не прерывается.
>
> Реестр НЕ меняет семантику метамодели (L-1/L-2, D-0057) и не является планом: план реализации
> строится в фазе 4 (`ROADMAP.md`, `MODULES.md`, приоритеты MVP-фич — Q-05).

## Правила маршрутизации

Каждое предложение при регистрации получает слой и адресата:

| Слой | Признак | Куда идёт | Ворота |
|---|---|---|---|
| **1. Семантика (метамодель)** | Меняет смысл данных: новый тип/свойство/отношение/ограничение (пример: «у задачи нужна повторяемость») | Очередь ADR; ядро заморожено (D-0056) — изменение только через новый ADR | Ответ пользователя + ADR |
| **2. Реализация / UX (плагин)** | Описывает, КАК пользователь что-то делает: формы, панели, хоткеи, drag-and-drop, пакетные операции, вставка из буфера | Фаза 4: `ROADMAP.md`, Q-05 (приоритеты MVP-фич); модульный уровень — `ARCHITECTURE.md` (принято / отложено / отклонено) | Чек-лист готовности, фаза 4 |
| **3. Данные (хранилище)** | Выражается существующими механизмами как данные: `Automation` (формы создания), `View` (представления), аспекты, предметные типы как данные M1 (D-0021) | ADR не нужен: описание типа (3c) или объект канонического хранилища `examples/vault/` | Прогон `npm test` |

Дополнительно:
- Пересечение с открытыми вопросами реализации (Q-45…Q-48) — связывается ссылкой.
- Статусы записи: `зарегистрировано` → `маршрутизировано` → `фаза 4` | `очередь ADR` | `данные M1`
  | `принято (ARCHITECTURE)` | `отложено` | `отклонено`.
- Отклонённое предложение не удаляется (строка сохраняется со статусом и обоснованием).

| WF-01 | 2026-10-21 | **Действия с пустыми (неразрешёнными) ссылками при создании заметки.** (а) Ссылка в свойстве **с контекстом** (свойство знает допустимые типы цели) → создаётся заметка типа из контекста свойства; (б) у свойства несколько контекстов → предлагается выбор из типов контекста; (в) ссылка в теле заметки или в свойстве без контекста → предлагается выбор из всех типов; (г) те же действия в контекстном меню пустой ссылки — пункт меню предлагает тип создаваемой заметки | 2 (реализация/UX) | Фаза 4: `ARCHITECTURE.md` §4.2 — уточнение модулей `EditorMenuIntegration`, `PickerModal`, `CreationService`; приоритеты — Q-05 | маршрутизировано | Частично уже спланировано: `EditorMenuIntegration` включает «создать объект из пустой ссылки», `PickerModal` фильтрует кандидатов по `target_types`/`target_facet`/`expected_media_roles`, `CreationService` выводит форму создания (ADR-0010 §2.4, §3.4). Источник контекста — `Property.target_types` (+ `expected_media_roles`) через `PropertyResolver`. Ограничение (а)/(б) для ссылок **в штатной панели свойств**: перехват виджета свойства невозможен через публичный API (`PropertyWidget`, `MetadataEditor` отсутствуют — D-0014); см. WF-03. В теле заметки: контекстное меню — `Workspace.on('editor-menu')` (публично); Live Preview — CM6, этап 2 (D-0045). ADR не требуется: семантика данных не меняется |
| WF-02 | 2026-10-21 | **Псевдоним из пустой ссылки.** В контекстное меню пустой ссылки добавить действие: создать псевдоним из неё — добавить текст ссылки в `aliases` конкретного существующего объекта и заместить пустую ссылку канонической ссылкой на этот объект | 2 (реализация/UX) | Фаза 4: расширение `EditorMenuIntegration` + `ObjectWriter`/`LinkResolver`; приоритеты — Q-05 | маршрутизировано | Публичный API достаточен: `editor-menu`, `processFrontMatter`, `fileToLinktext`/`generateMarkdownLink` (D-0014). Семантические ограждения уже нормативны: `aliases` — только реальные псевдонимы, дубли внутри объекта — `error`, дубль `title` и общий псевдоним — `warn` (ADR-0004); запись ссылки — каноническая форма `[[{title} ({PREFIX}-{id})\|{title}]]` (ADR-0002 §4). Запись псевдонима меняет ДРУГОЙ объект (цель) — поток с подтверждением. ADR не требуется |
| WF-03 | 2026-10-21 | **Виджет кастомных свойств, замещающий встроенный** (штатный виджет панели свойств Obsidian) | 2 (реализация/UX) | Фаза 4: оценка осуществимости; при подтверждении невозможности — фиксация в `ARCHITECTURE.md` §4.4 с альтернативами | маршрутизировано, **конфликт с P-API-1** | Прямо упирается в D-0014: `PropertyWidget`, `registerPropertyWidget`, `MetadataEditor` в `obsidian.d.ts` ОТСУТСТВУЮТ — замещение штатного виджета свойства невозможно публичным API (проверено). Решение «отклонено с альтернативами / отложено до появления API» — за пользователем в фазе 4 |
| WF-04 | 2026-10-21 | **Замещение отображения имени файла читаемым названием** из свойства (наподобие плагина Front Matter Title): в проводнике и интерфейсе показывать `title`/`label` без хвоста `({PREFIX}-{id})` | 2 (реализация/UX) | Фаза 4: **пересмотр отклонённого** `ARCHITECTURE.md` §4.4 (`TitleResolver` + 13 адаптеров подмены отображения); возможна новая проверка P-API-1 в части DOM-манипуляций | маршрутизировано, **пересмотр отклонённого** | Отклонено в фазе 2 по двум основаниям: (1) подмена имени файла недоступна через публичный API; (2) «потребность устранена ADR-0002 (имя файла читаемо)». Предложение пользователя возобновляет (2): имя читаемо, но стабильный хвост `(PREFIX-ULID)` — визуальный шум в проводнике/вкладках. Варианты для фазы 4: сохранить отклонение; DOM-манипуляции поверх штатных элементов (так делает Front Matter Title; это не вызовы частного API, но недокументированное вмешательство в интерфейс — хрупкость при обновлениях, нужна интерпретация P-API-1); частичное покрытие в собственных представлениях уже есть: `LabelProvider` → `displayName` в Bases (публично, MVP). Решение — за пользователем; при выборе DOM — оценка рисков и границ |
| WF-05 | 2026-10-21 | **`created_at`/`updated_at` как видимые свойства; `updated_at` автоматически обновляется при сохранении заметки** | 2 (реализация/UX) | Фаза 5: `ObjectWriter` (+ проверка этапа 0 по D-0065); отображение — `EntityPanel`/штатная панель | маршрутизировано | Публичный API достаточен: `vault.on('modify')` + `processFrontMatter` (D-0014). Обязательные оговорки: (1) запись даты — закавыченной строкой с offset (D-0065, `ARCHITECTURE.md` §4.1.2: передача `Date` в путь записи запрещена); (2) защита от петли: собственная запись триггерит `modify` повторно — игнорировать свои изменения/дебаунс; (3) поведение штатной панели свойств (приведение строки к `Date` при пересохранении) проверяется на этапе 0 фазы 5 — уже запланировано D-0065. Семантика контракта не меняется: `updated_at` — «момент последнего изменения»; редакционное уточнение нормы автообновления — в `NAME_MAPPING.md` §8 при реализации. ADR не требуется |
