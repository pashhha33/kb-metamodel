# Сущность: Category (`category`)

## 1. Определение

`Category` — определение M1, **значение оси классификации** (узел иерархии фасета): принадлежит
ровно одному фасету (`Category.facet`, ADR-0005 — одна категория = один фасет), может иметь
родителя (`parent`, 0..1 при `hierarchy_mode: strict`). Корень определяется пустым `parent`
(`null` либо отсутствие поля, F-3.11); искусственный объект «Корень» не создаётся. Назначения
хранятся **на объектах** в полях `cat_<facet_key>` (ADR-0007), а не на категории. Категории
дополнительно служат: триггерами аспектов (`Aspect.trigger_categories`, ADR-0008) и значениями
свойств-словарей (`Relation.role` через фасет `char_role`, D-0064).

**Проверка различимости:** заметка является `Category`, если её `type: category` и есть ссылка
`facet`. НЕ является `Category`: свободная метка (`tags` — без валидации и иерархии, граница
D-0022), ось (`Facet`), тип объекта (`ObjectType` — «писатель» как профессия является категорией,
а типом человека является `person`: правило роли D-0026).

## 2. Пример из жизни

- **Корень** — `examples/vault/taxonomy/Писатель (CAT-…3A4).md`: фасет `profession`, `parent`
  отсутствует; одновременно триггер аспекта `literary_person` (активация включает потомков,
  ADR-0008 — потомки `Прозаик` → `Романист` тоже активируют).
- **Потомок** — `examples/vault/taxonomy/Романист (CAT-…3A5).md`: `parent: [[Прозаик (CAT-…3A6)]]`;
  назначен Булгакову в `cat_profession` наряду с «Врачом» (две профессии, `0..n`).
- **Значение словаря** — `examples/vault/taxonomy/Главный герой (CAT-…3G8).md`: фасет `char_role`;
  не назначается в `cat_*`, а используется как значение `Relation.role` (D-0064).
- **Контрпример** — `tags: [булгаков]` в заметке объекта: свободная метка без фасета и проверки.

## 3. Место в классификации

- Слой: **M1**, определение (системный тип ядра). Уровень 3 из 4 цепочки
  `Taxonomy → Facet → Category → Object` (ADR-0005).
- Смежные типы и отличия: `Facet` — владелец (ссылка только вверх); `Category` — единственный
  уровень с иерархией внутри себя (`parent`); назначения — уровень 4 (объекты, поля `cat_<key>`).
- Роль `title` (D-0063): **отображаемое название** («Писатель»); ключа категория не имеет.
  `label` — подпись; уникальность названия в пределах фасета обеспечивает `classif.r8`.

## 9. Идентичность, дубли и слияние

- Ключ идентичности: `id` (ULID). Переименование `title` допустимо — назначения ссылаются
  по стабильной части `(CAT-{id})` и остаются валидными (ADR-0002).
- Обнаружение дублей: `classif.r8` (одно название в фасете), `classif.r9` (межфасетные омонимы).
- Слияние категорий: процедура ADR-0009 — перевод ссылок в `cat_*`/`trigger_categories`/`role`,
  связь `merged_into`, архивация дубля.
