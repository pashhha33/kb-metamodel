# Сущность: MediaAsset (`media_asset`)

## 1. Определение

`MediaAsset` — **системный тип M1, объекты которого являются экземплярами, а не определениями**:
медиаобёртка, реификация ссылки на файл хранилища. Вводится потому, что у связи файла с объектом
есть атрибуты (роли, источник, автор, лицензия, метод создания); `Relation` поверх обёртки был бы
двойной реификацией и запрещён (ADR-0011 §3.1). Связь обёртки с объектами хранится **в свойствах
объектов** (`Book.cover`, `Person.portrait`, `Organization.logo`, …), обёртка список объектов не
хранит — обратный список вычисляется (D-0049). Сам медиафайл обёрткой не является.

**Проверка различимости:** заметка является `MediaAsset`, если её `type: media_asset` и заполнены
`file` и `media_kind` (`relation.r1`-аналог — обязательность по схеме). НЕ является `MediaAsset`:
бинарный файл в `assets/` (у него нет frontmatter), галерея (`Gallery` — предметный тип-подборка),
встраивание `![[файл]]` в теле заметки (обёртка нужна только при роли или метаданных — `media.r8`).

## 2. Пример из жизни

- `examples/vault/media/Обложка «Мастера и Маргариты» (MEDIA-…2GC).md`: две роли (`cover`,
  `preview`), галерея, назначение `cat_creation_method: [Генерация ИИ]` и **активированный
  аспектом** набор полей метода (`prompt`, `model`, `seed`) — поля аспекта допустимы благодаря
  открытому словарю фрагмента (D-0068).
- `examples/vault/media/Портрет Михаила Булгакова (MEDIA-…2GE).md`: одна обёртка в двух ролях
  (`portrait` книги… точнее `portrait` человека и `preview` иллюстраций), без `author`
  (автор фотографии неизвестен), `cat_creation_method: [Фото]`.
- **Контрпример** — `examples/vault/assets/Обложка «Мастера и Маргариты» (MEDIA-…2GC).png`:
  бинарный файл-заглушка; имя построено по конвенции ADR-0011 §3.7 (D-0055), но заметкой не является.

## 3. Место в классификации

- Слой: **M1**, системный тип-экземпляр (как `Relation`): форма статична и задана ядром,
  определения `ObjectType` не имеет; в ссылочных полях определений адресуется голой строкой
  `media_asset` (D-0067).
- Смежные типы и отличия: `Gallery` — 9-й конкретный предметный тип, подборка обёрток без поля
  состава (сортировка — свойство представления, D-0053); `Property` — связь «объект → обёртка»
  хранится свойством объекта с `expected_media_roles`; `Facet creation_method` + аспект
  `ai_generated_media` — классификация и атрибуты метода создания (ADR-0011 §3.3).
- Роль `title` (D-0063): **отображаемое название**; `label` **не обязателен** — `naming.r10`
  на экземпляры системных типов не распространяется (D-0066), подпись в UI берётся из `title`.

## 9. Идентичность, дубли и слияние

- Ключ идентичности: `id` (ULID). **Переименование бинарного файла — только при создании и по
  явной команде** (§3.7, D-0055): ссылка `file` и имя файла обёртки меняются согласованно.
- Дубли обёрток на один файл легитимны только при разных ролях и фиксируются `media.r6` (warn);
  слияние обёрток — процедура ADR-0009 с переводом ссылок из свойств объектов.

## 12. Открытые вопросы и расширения

- [x] **F-3.12 / `label`** — закрыто D-0066: необязателен.
- [x] **F-3.24 / аспектные поля** — закрыто D-0068: фрагмент с открытым словарём
      (`unevaluatedProperties: true`), эффективный набор проверяется межобъектно.
- [ ] Источник из сетевого адреса (`UrlMediaSource`) отложен — конфликт с рамкой «офлайн»
      (D-0054, отклонение 3); `AutoFillFromMedia` (метаданные из файла в поля) — после MVP,
      требует allowlist (ARCHITECTURE §4.3).
- Косметика инструментария: многострочные строковые значения в каноне сериализуются экранированным
      потоковым стилем; блоковая форма (`|`) читалась бы лучше — кандидат в правки генератора
      (не нормативно).
