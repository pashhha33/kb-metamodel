# Сущность: View (`view`)

## 1. Определение

`View` — определение M1 **представления**: какие типы объектов показывать (`target_types`),
каким механизмом (`mechanism` — абстрактный идентификатор, без названий инструментов в enum,
L-1/D-0057), в какой конфигурации (`definition` — текст в формате выбранного механизма)
и активно ли оно (`is_active`). Разделение «активное / архив» — задача представления, а не
хранения (ADR-0009 §3.1): фильтры `status != archived` живут в `definition`. Не является
самим рендерингом и не является служебным файлом механизма (файлы баз — производные артефакты
плагина, фаза 5).

**Проверка различимости:** заметка является `View`, если её `type: view` и заполнены
`target_types`, `mechanism`, `is_active`. НЕ является `View`: производный файл механизма
(генерируется плагином из определения), навигационная панель последовательности (модуль
представления плагина, отдельного определения не требует), запрос от руки в поиске.

## 2. Пример из жизни

- `examples/vault/views/Карточка книги (VIEW-…2A2).md`: `mechanism: card`, `target_types` —
  wikilink на определение `Книга`; `definition` задаёт фильтры (`status` без архива), порядок
  (`title`, `publication_date`) и состав полей (`cover`, `publisher`, `cat_genre`, `cat_tone`,
  `isbn`, `page_count`).
- Контрпример: `examples/vault/automations/create_chapter (AUTO-…5A3).md` — автоматизация
  создания, а не отображения; enum `mechanism` у типов общий, роли разные.

## 3. Место в классификации

- Слой: **M1**, определение (системный тип ядра).
- Смежные типы и отличия: `Automation` — действие/форма создания (общий enum `mechanism`);
  `ObjectType` — цель `target_types` (wikilink на определения; имена системных типов запись
  D-0067 на `View.target_types` в редакции 0.15.0 **не распространяется** — см. §12).
- Роль `title` (D-0063): **отображаемое название** («Карточка книги»); подпись — `label`.

## 7. Даты и интервалы

Контрактные `created_at`/`updated_at` — ISO 8601 с offset, закавыченной строкой (D-0065).

## 8. Ограничения и правила валидации

| ID правила | Уровень | Формулировка (кратко) | Кто проверяет |
|---|---|---|---|
| `meta.r7` | error | `target_types` не пуст; `mechanism` входит в enum | схема |
| `view.r1` | error | у активного представления `target_types` разрешим | песочница |
| `view.r2` | warn | целевой тип без свойств, пригодных для колонок | песочница |
| `contract.r6`, `r11`, `r12` | error/warn | `title` не пуст; имя файла `{title} ({VIEW}-{id}).md` | схема + песочница |
| `naming.r10` | error | `label` присутствует | схема |
| `meta.r13` | warn | определение не используется — для `View` критерий: `is_active: false` и нет обращений | песочница |

## 9. Идентичность, дубли и слияние

- Ключ идентичности: `id` (ULID). Переименование `title` допустимо.
- Дубли представлений (одинаковые `target_types` + `mechanism` + `definition`) — ревью; слияние —
  процедура ADR-0009 (архивация дубля).

## 10. Представления

Мета-уровень: `View` сам является определением представлений. В UI плагина определения показываются
списком в панели (подпись `label`, признак активности); активные представления рендерятся
механизмами (см. `docs/plugin/ARCHITECTURE.md` §4.2 — собственные представления, навигация,
панель объекта).

## 11. Пример заметки

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2A2
type: view
title: Карточка книги
label: Карточка книги
target_types:
  - "[[Книга (OTYPE-01J8Z6M4K2Q7V9X3N5B0C1D2HH)|Книга]]"
mechanism: card
definition: "filters:

  \  status: [capture, draft, normalizing, active]

  order: [title, publication_date]

  show: [cover, publisher, cat_genre, cat_tone, isbn, page_count]\n"
is_active: true
description: "Карточка книги: обложка, издательство, жанр, тональность, ISBN и объём. Архивные книги исключены фильтром."
lifecycle: standard
status: active
created_at: "2026-10-21T10:29:00+03:00"
updated_at: "2026-10-21T18:00:00+03:00"
---
```

> Запись `definition` экранированным потоковым стилем — артефакт сериализации генератора;
> семантически это одна многострочная строка. Блоковая форма (`|`) — косметическая правка
> генератора (см. `media_asset.md` §12).

## 12. Открытые вопросы и расширения

- [ ] **Формат `definition`** не нормализован ядром (определяется механизмом): стандартизация
      схемы `definition` для каждого механизма — фаза 4/5 вместе с прототипом `registerBasesView`
      (Q-45, ARCHITECTURE этап 0).
- [ ] **Запись системных типов в `View.target_types`** не поддержана (D-0067 ограничен
      `applicable_types` и `Property.target_types`): представление «все медиаобёртки» невыразимо.
      Потребности в MVP нет (галереи покрываются типом `Gallery`); при появлении — расширение
      `system_type_name` на это поле через реестр решений.
- [ ] `mechanism: kanban`/`query`/`custom` — заделы: реализация в MVP только у механизмов списка
      ARCHITECTURE §4.2 (остальные — этап отложенных).
