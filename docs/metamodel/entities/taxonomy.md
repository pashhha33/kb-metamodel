# Сущность: Taxonomy (`taxonomy`)

## 1. Определение

`Taxonomy` — определение M1, **контейнер осей классификации** (фасетов), а не иерархия категорий
(терминология закреплена D-0025: наша `Taxonomy` = контейнер, иерархия = `Facet` с
`hierarchy_mode`). Таксономия задаёт: границу применимости классификации (`applicable_types` —
каким типам объектов можно назначать её категории) и значения по умолчанию для фасетов
(`hierarchy_mode`, `assignment_cardinality`, `root_requirement`). Состав фасетов **не хранится**:
он вычисляется из ссылок `Facet.taxonomy` (ADR-0005, закрывает C-15); ссылки хранятся только вверх.

**Проверка различимости:** заметка является `Taxonomy`, если её `type: taxonomy` и она группирует
фасеты и ограничивает типы классифицируемых объектов. НЕ является `Taxonomy`: ось классификации
с иерархией и настройками (`Facet`), значение оси (`Category`), назначение категорий объекту
(поля `cat_<facet_key>` на объектах, ADR-0007).

## 2. Пример из жизни

- **Область классификации** — `examples/vault/taxonomy/Медиа (TAX-…3G1).md`:
  `applicable_types: [media_asset]` — голая строка для системного типа (D-0067); одна ось —
  `creation_method` (ADR-0011 §3.3).
- **Ссылки на ObjectType** — `examples/vault/taxonomy/Люди и организации (TAX-…3A1).md`:
  `applicable_types` — wikilink-ссылки на определения `Человек` и `Организация`; оси —
  `profession`, `org_type`.
- **Таксономия-словарь** — `examples/vault/taxonomy/Словари значений (TAX-…3E8).md`:
  `applicable_types: [relation]`, ровно один элемент (D-0064): её категории (`char_role`) не
  назначаются объектам в `cat_*`, а используются как значения свойства `Relation.role`.
- **Контрпример** — `examples/vault/taxonomy/profession (FACET-…3A3).md` (`type: facet`):
  ось с иерархией и настройками — это `Facet`, владеющая ссылкой на таксономию.

## 3. Место в классификации

- Слой: **M1**, определение (системный тип ядра). Уровень 1 из 4 классификационной цепочки
  `Taxonomy → Facet → Category → Object` (ADR-0005).
- Смежные типы и отличия: `Facet` — ось внутри таксономии (настройки иерархии принадлежат фасету,
  таксономия хранит лишь значения по умолчанию); `Category` — значение оси; уровень `Domain`
  над таксономией в MVP не вводится (D-0023), границу задаёт `applicable_types`.
- Роль `title` (D-0063): **отображаемое название** («Медиа», «Люди и организации»); ключа
  таксономия не имеет — адресуется ссылкой и `id`.

## 5. Связи

|---|---|---|---|---|---|---|

у объектов — поля `cat_<facet_key>` (через фасеты, ADR-0007).

## 8. Ограничения и правила валидации

| ID правила | Уровень | Формулировка (кратко) | Кто проверяет |
|---|---|---|---|
| `meta.r5` | error | `applicable_types` не пуст и элементы разрешимы (wikilink — по индексу, голая строка — по реестру системных типов) | схема (minItems) + песочница |
| `meta.r6` | error | `Facet.taxonomy` разрешима (ссылки только вверх) — проверяется на фасете | песочница |
| `classif.r2` | error | тип объекта входит в `applicable_types` таксономии назначенной категории (с учётом наследования и D-0064 для словарей) | песочница |
| `classif.r9` | warn | одинаковые названия категорий в разных фасетах одной таксономии — вероятно нарушение ортогональности (D-0024) | песочница |
| `contract.r6`, `r11`, `r12` | error/warn | `title` не пуст; имя файла `{title} ({TAX}-{id}).md`; ≤ 60 | схема + песочница |
| `naming.r10` | error | `label` присутствует | схема |
| `meta.r13` | warn | таксономия без фасетов — возможно, мёртвая | песочница |

## 9. Идентичность, дубли и слияние

- Ключ идентичности: `id` (ULID). Переименование `title` допустимо (имя файла меняется, ссылки
  обновляет процедура ADR-0009).
- Дубль таксономии (две таксономии об одной области) — ревью; слияние — перенос ссылок
  `Facet.taxonomy` и архивация дубля (`merged_into`).
- Уровень `Domain` (объединение таксономий) отклонён для MVP (D-0023); задел — необязательное
  поле `Taxonomy.domain`.

## 10. Представления

| Представление | Как отображается | Приоритет (фаза 4, Q-05) |
|---|---|---|
| Навигация по классификации | таксономия → фасеты → категории (дерево) | MVP |
| Фильтры представлений | граница `applicable_types` сужает выбор категорий | MVP |
| Форма назначения категорий | оси только тех таксономий, которые применимы к типу объекта | MVP |

## 12. Открытые вопросы и расширения

- [ ] **A-5 (допущение):** значения по умолчанию для фасетов хранятся в полях с теми же именами
      (`hierarchy_mode`, `assignment_cardinality`, `root_requirement`), а не с суффиксом `_default` —
      подтверждено практикой 3c, остаётся допущением схемы (REPORT §3).
- [ ] **F-3.28 (новое, редакционное):** description поля `title` во фрагментах `taxonomy`,
      `category`, `relation`, `object_type` говорит «ключом является label» — `label` является
      подписью (ADR-0001, D-0063), а не ключом; у этих типов ключа нет (кроме `ObjectType.type_id`,
      ADR-0012). Правка description — в следующий перевыпуск схемы.
- Задел: `Taxonomy.domain` (D-0023), `hierarchy_mode: polyhierarchical` (enum объявлен,
      семантика много parent — после MVP).
