# Сущность: Aspect (`aspect`)

## 1. Определение

`Aspect` — определение M1 **активируемого набора свойств** (12-й тип ядра, реализует требование
R-TRIGGER, ADR-0008): категории-триггеры (`trigger_categories`), активируемые свойства
(`properties`), ужесточения в контексте аспекта (`property_overrides`) и признак активности
(`is_active`). Назначение объекту любой триггерной категории **или её потомка** активирует аспект:
объект получает поля аспекта сверх эффективного набора своего типа. Алгоритм разрешения ред. 2:
inherited → own → universal → **triggered** → override ?? default; аспекты упорядочиваются по
возрастанию `id`; конфликт двух аспектов по одному свойству — `error` при загрузке (`aspect.r2`).
Значения аспектных полей **не удаляются автоматически** при снятии триггера (принцип S6) —
поле остаётся и помечается предупреждением (`aspect.r1`, `property.r6`).

**Проверка различимости:** заметка является `Aspect`, если её `type: aspect` и заполнены
`trigger_categories`, `properties`, `is_active`. НЕ является `Aspect`: универсальное свойство
(применяется ко всем типам без триггера — `scope: universal`), семейное свойство (ветви
иерархии — `scope: family` + `applies_to`, без категорий), категория (триггер — лишь ссылка).

## 2. Пример из жизни

- `examples/vault/aspects/literary_person (ASPECT-…3E1).md`: триггеры — категории «Писатель»,
  «Поэт», «Драматург» (активация включает потомков: «Романист» — потомок «Прозаика»… ветвь
  «Писателя»); свойства `pen_name`, `literary_period`, `awards`; `property_overrides` ужесточает
  `pen_name` до обязательного. Булгаков — «Романист» (потомок ветви) + «Врач»: аспект активен.
- `examples/vault/aspects/ai_generated_media (ASPECT-…3F4).md`: аспект **на системном типе** —
  триггер «Генерация ИИ» (фасет `creation_method`), свойства `prompt`, `model`, `seed`,
  `source_image`; поля появляются на медиаобёртках благодаря открытому словарю фрагмента
  `media_asset` (D-0068) — второе применение `Aspect` после профессии (D-0051).
- **Контрпример** — свойство `publisher` (`scope: universal`): применяется ко всем типам
  автоматически, триггеров не имеет.

## 3. Место в классификации

- Слой: **M1**, определение (системный тип ядра).
- Смежные типы и отличия: `Category` — триггеры (через `trigger_categories`; категории-триггеры
  считаются используемыми в `classif.r7`, D-0069); `Property` — активируемые свойства;
  `ObjectType.property_overrides` — ужесточения типа (аспектные overrides применяются после,
  порядок — по возрастанию `id` аспектов).
- Роль `title` (D-0063): **ключ** (EN snake_case: `literary_person`, `ai_generated_media`);
  подпись — `label`; имя файла строится по ключу.
- Поле `layer`: у аспекта нормативно `system` (ADR-0008 §3.1, §3.7); объявлено во фрагменте
  с 0.14.0 (F-3.20), обязательно только у `ObjectType`. Область действия `layer` на прочие
  определения M1 — открытый вопрос **F-3.3 / Q-68** (§12).

## 8. Ограничения и правила валидации

| ID правила | Уровень | Формулировка (кратко) | Кто проверяет |
|---|---|---|---|
| `aspect.r1` | warn | значение аспектного свойства есть, а аспект не сработал (проверяется на объекте M0) | песочница |
| `aspect.r2` | error | два активных аспекта задают несовместимые ограничения одного свойства — при загрузке | песочница |
| `aspect.r3` | error | `trigger_categories` не пуст, цели — `Category` | схема (minItems) + песочница |
| `aspect.r4` | error | `properties` не пуст, цели — `Property` | схема (minItems) + песочница |
| `aspect.r5` | warn | аспект переопределяет свойство, уже заданное типом, с другими ограничениями | песочница |
| `aspect.r6` | info | `is_active: false` — аспект выключен | песочница |
| `naming.r10` | error | `label` присутствует | схема |
| `contract.r6`, `r11`, `r12` | error/warn | `title` не пуст; имя файла по ключу | схема + песочница |
| `classif.r7` | warn | категории-триггеры считаются используемыми (D-0069) | песочница |
| `property.r1…r6` | error/warn | значения аспектных полей на объектах (эффективный набор) | песочница / валидатор |

## 9. Идентичность, дубли и слияние

- Ключ идентичности: `id` (ULID); порядок применения аспектов зависит от `id` — пересоздание
  аспекта с новым `id` меняет порядок разрешения конфликтов (осознанно: порядок детерминирован).
- Дубли аспектов (одинаковые триггеры и свойства) — ревью; слияние — ADR-0009 с переносом
  триггеров; значения полей на объектах не удаляются (S6).

## 12. Открытые вопросы и расширения

- [ ] **F-3.3 / Q-68:** область действия `layer` — только `ObjectType` (обязателен) и `Aspect`
      (объявлен, необязателен) либо все определения M1. Решение пользователя; при сохранении
      статуса-кво находка закрывается формулировкой «`layer` описывает принадлежность типа
      иерархии метамодели или домена; прочие определения в ней не нуждаются».
- [x] **F-3.20** — закрыто: `layer` объявлен во фрагменте (0.14.0), пример ADR-0008 §3.1
      проходит схему.
- [ ] Заделы триггеров (`trigger_relation_types`, `trigger_conditions`, `trigger_types`, A-6):
      семантика «ИЛИ» относительно категорий не нормирована — активация по ним в MVP не
      реализуется; возврат по потребности через реестр решений.
