# Сущность: PropertyType (`property_type`)

> **Устаревший механизм (F-3.2, D-0071).** Тип сохранён в ядре M1 как deprecated: набор типов
> значений закрыт перечислением `value_type` из 6 значений на уровне M2 (ADR-0003, закрывает C-22),
> объекты `PropertyType` не несут самостоятельной семантики. Новые объекты не создаются
> (плагин не предлагает тип при создании); существующие 6 объектов сохранены как историческая
> запись; префикс `PTYPE` не переиспользуется (`TYPE_PREFIX_REGISTRY` §1 R8).

## 1. Определение

`PropertyType` — определение M1, исторически описывавшее один тип значения свойств
(текст, число, дата, дата-время, логическое, ссылка). В действующей модели ту же роль играет
закрытый enum `value_type` во фрагменте `Property` и в `common/enums.json`: правило `meta.r1`
обеспечивается перечислением, разрешение ссылки на объект `PropertyType` не требуется
(x-notes фрагмента). Не является типом объектов M0 и не является свойством.

**Проверка различимости:** заметка является `PropertyType`, если её `type: property_type`,
а `title` совпадает с одним из 6 значений enum `value_type`. НЕ является `PropertyType`:
определение поля (`Property`), значение свойства, тип объекта (`ObjectType`).

## 2. Пример из жизни

- Пример: `examples/vault/property-types/text (PTYPE-01J8Z6M4K2Q7V9X3N5B0C1D2C1).md` —
  `title: text`, `label: Текст`, `lifecycle: deprecated`. Полный набор vault: `text`, `number`,
  `date`, `datetime`, `boolean`, `reference` (6 объектов, по числу значений enum).
- Контрпример: `examples/vault/properties/isbn (PROP-…2H1).md` — определение свойства
  со `value_type: text`, а не тип значения.

## 3. Место в классификации

- Слой: **M1**, определение (системный тип ядра, deprecated — D-0071).
- Смежные типы: `Property.value_type` хранит значение enum, а не ссылку на `PropertyType`;
  ядро M1 остаётся из 12 типов (счёт не меняется, D-0071).
- Роль `title` (D-0063): **ключ** — совпадает со значением enum `value_type`; подпись — `label`.

## 5. Связи

Связей не имеет: ни одно определение не ссылается на объекты `PropertyType` (`meta.r1`
обеспечен enum). Обратных ссылок в нормативной модели нет; исторические упоминания возможны
в черновиках `inbox/` (read-only).

## 6. Enum и справочники

| Enum | Допустимые значения | Семантика | Где определён |
|---|---|---|---|
| `value_type` | `text`, `number`, `date`, `datetime`, `boolean`, `reference` | закрытый набор типов значений (M2) | `schema/0.14.0/common/enums.json` |
| `lifecycle` | `experimental`, `standard`, `deprecated`, `archived` | жизненный цикл | там же |

## 7. Даты и интервалы

Контрактные `created_at`/`updated_at` — ISO 8601 с offset, закавыченной строкой (D-0065).

## 8. Ограничения и правила валидации

| ID правила | Уровень | Формулировка (кратко) | Кто проверяет |
|---|---|---|---|
| `meta.r1` | error | `Property.value_type` — значение из закрытого набора | схема (enum; разрешение ссылки на объект не требуется) |
| `naming.r10` | error | `label` присутствует | схема |
| `contract.r6`, `r11`, `r12` | error/warn | `title` не пуст; имя файла по ключу | схема + песочница |
| `meta.r11` | warn | deprecated, но используется — для `PropertyType` не срабатывает: определений, ссылающихся на него, нет | песочница |
| `meta.r13` | warn | мёртвое определение — объекты с `lifecycle: deprecated` песочницей не помечаются | песочница |

## 9. Идентичность, дубли и слияние

- Ключ идентичности: `id` (ULID). Набор из 6 объектов закрыт: новые не создаются (D-0071),
  дубли невозможны (уникальность `title` = уникальность значения enum).
- Исключение типа из ядра отклонено (Q-63 = B): потребовало бы ADR, перевыпуска схемы и правки
  счёта «12 типов» без содержательного выигрыша — enum остаётся в схеме в любом случае.

## 10. Представления

Не отображается: плагин не предлагает тип при создании и не строит по нему UI. Объекты видны
в каноническом хранилище как исторический каталог `property-types/`.
