# Реестр префиксов типов (`TYPE_PREFIX`)

## 1. Правила (нормативные, ADR-0002 п. 2 + ADR-0005 §3.7)

| # | Правило | Проверка |
|---|---|---|
| R1 | Только ASCII: регулярное выражение `^[A-Z][A-Z0-9]{2,11}$` | при сохранении `ObjectType` |
| R2 | Длина 3–12 символов | при сохранении |
| R3 | Уникальность по **точному совпадению всей строки**, а не по началу строки | при сохранении, по всему реестру |
| R4 | Дефисы запрещены | регулярным выражением R1 |
| R5 | Обязателен для конкретного типа (`is_abstract: false`) | при сохранении |
| R6 | Отсутствует (`null`) у абстрактного типа (`is_abstract: true`) | при сохранении |
| R7 | Не изменяется после создания типа | при изменении `ObjectType` |
| R8 | Не переиспользуется после удаления или архивирования типа | постоянно, по журналу |
| R9 | Кириллица и омоглифы запрещены | проверкой кодовых точек: только `U+0041`–`U+005A`, `U+0030`–`U+0039` |

**Про R3.** Правило введено из-за противоречия C-08: в черновиках одновременно использовались
`PROPERTY-000001` (свойство) и `PROPERTY-TYPE-000001` (тип свойства). Второй префикс начинается
с первого, и требование «префикс уникален» без уточнения способа сравнения допускало обе трактовки.
Сравнение по полному совпадению устраняет неоднозначность: `PROP` и `PROJ` не конфликтуют,
потому что разбираются как разные строки, а техническая часть имени файла всегда ограничена
скобками и дефисом перед ULID.

**Про R9.** Правило введено из-за C-06: в Спецификации §5 префикс `CHARACTЕR` содержал кириллическую
«Е» (U+0415). Визуально неотличимо от латинской, ломает уникальность и поиск.

## 6. Запрещённые к использованию значения

| Значение | Причина |
|---|---|
| `PROPERTY` | Коллизия восприятия с `PROP` / `PTYPE`. Исторически использовался в черновиках (C-08) |
| `PROPERTY-TYPE` | Нарушает R4 (дефис). Заменён на `PTYPE` |
| `OBJECT-TYPE` | Нарушает R4. Заменён на `OTYPE` |
| `RELATION-TYPE` | Нарушает R4. Заменён на `RTYPE` |
| `CHARACTЕR` | Кириллическая «Е» (U+0415), нарушает R9. Заменён на `CHAR` |
| `DOC` | Тип `Documentation` исключён из ядра (X-05, C-37) |
| `SB` | Зарезервировано под служебную область `.sb/` |
| Любые значения длиной < 3 | Нарушают R1 |

## 7. Проверка уникальности (алгоритм для плагина)

```
вход: candidate_prefix, реестр всех ObjectType
1. нормализовать: trim, upper
2. проверить R1 регулярным выражением ^[A-Z][A-Z0-9]{2,11}$
3. проверить R9: все кодовые точки в диапазонах U+0041–U+005A, U+0030–U+0039
4. проверить отсутствие в §6 (запрещённые значения)
5. проверить точное совпадение (§6.3) со всеми type_prefix конкретных типов
   и со всеми зарезервированными (§5)
6. результат: ok | ошибка с указанием конфликтующего типа
```
